# Inochi Agent Tools v1.1 daily-use bundle

Issue #23 makes the proven v1 CLI and stdio MCP server usable without keeping the caller in the repository root. The supported v1.1 unit is a reproducible local bundle. It preserves the v1 semantic core and pinned native contract; it does not introduce a second authoring implementation.

## Prerequisites

Build hosts need Node.js 22+, npm, Git, DUB, and LDC >= 1.40.0. The reproducible CI authority uses LDC 1.40.0. Linux/WSL acceptance also installs Xvfb, xdotool, X11 utilities, SDL2 development files, and FreeType development files because `npm run v1:ci` retains official Creator compatibility acceptance.

Windows users should use WSL2 with a current Ubuntu distribution for the full reproducible build/acceptance path. The generated bundle also contains PowerShell launchers for invoking an already-built compatible bundle from Windows. Do not mix a Linux native bundle with native Windows binaries: rebuild/package for the platform that will execute the bundle.

## Fresh checkout and bundle build

From a fresh checkout:

```bash
git clone https://github.com/MohamedXIV/inochi-agent-tools.git
cd inochi-agent-tools
npm ci
npm run v1.1:package:ci
```

`v1.1:package:ci` first runs the complete `v1:ci` authority, then builds `.build/bundle` and smoke-tests the packaged CLI and MCP server from an unrelated temporary working directory against real `.inp` artifacts. A faster rebuild after the full gate has already passed is:

```bash
npm run v1.1:bundle
```

The bundle contains the built core/CLI/SDK/MCP packages, their runtime dependencies, the native host/bridge, and installation-relative launchers. Native discovery is relative to the installed bundle, not to the caller's current directory. `IAT_NATIVE_DIR` remains an explicit development/debug override and should normally be unset.

## CLI daily use

Linux/WSL:

```bash
/path/to/inochi-agent-tools/.build/bundle/inochi-agent --json puppet validate --input /absolute/path/character.inp
```

PowerShell with a compatible Windows bundle:

```powershell
& 'C:\path with spaces\inochi-agent-tools\.build\bundle\inochi-agent.ps1' --json puppet validate --input 'C:\puppets\character.inp'
```

The launchers quote their installation paths and set the native directory themselves, so the command may be run from any working directory.

## MCP client configuration

For Linux/WSL clients, point the stdio command directly at the installed launcher using an absolute path:

```json
{
  "mcpServers": {
    "inochi-agent-tools": {
      "command": "/home/me/inochi-agent-tools/.build/bundle/inochi-agent-mcp",
      "args": []
    }
  }
}
```

For a Windows MCP client using a compatible Windows bundle, use PowerShell as the command so `.ps1` execution is explicit:

```json
{
  "mcpServers": {
    "inochi-agent-tools": {
      "command": "powershell.exe",
      "args": [
        "-NoProfile",
        "-ExecutionPolicy",
        "Bypass",
        "-File",
        "C:\\path with spaces\\inochi-agent-tools\\.build\\bundle\\inochi-agent-mcp.ps1"
      ]
    }
  }
}
```

Do not configure a repository working directory for MCP. The bundle is specifically required to work when the client starts it from an unrelated CWD.

## Upgrade and rebuild

The bundle is generated output and should not be edited in place. To upgrade, update the source checkout to the intended reviewed revision, reinstall the exact lockfile dependencies, and rebuild:

```bash
git pull --ff-only
npm ci
npm run v1.1:package:ci
```

Replace client paths only if the bundle installation path changed. The pinned Inochi2D revision and patch fingerprint remain governed by `npm run v1:ci`.

## Troubleshooting

- If the launcher reports a missing native host or shared library, confirm that the bundle's `native/` directory exists and that the bundle was built for the executing platform. Do not solve this by changing the caller CWD.
- If `IAT_NATIVE_DIR` is set in the environment, unset it and retry unless intentionally testing a development native build; the override takes precedence over installation-relative discovery.
- If a path contains spaces, invoke the generated launcher rather than calling package JavaScript or native binaries manually.
- If a Windows client is targeting a WSL-built bundle, run the MCP server through the WSL environment instead of attempting to load Linux native artifacts in a Windows process.
- For suspected regressions, run `npm run verify`, `npm run v1:ci`, and `npm run v1.1:package:ci`. A daily-use packaging change is not acceptable if any of these gates regress.

## Acceptance boundary

The package smoke is intentionally real-artifact acceptance: the bundle is launched from an unrelated CWD and the CLI and stdio MCP server operate on genuine v1-authored `.inp` files. Synthetic fixtures remain limited to narrow unit tests. Creator GUI automation remains compatibility infrastructure and is not a normal runtime dependency of the packaged CLI or MCP server.
