# M3 MCP Server and TypeScript SDK Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose the existing semantic authoring capabilities through a public TypeScript SDK and a stdio MCP server, with stable semantic schemas and real-artifact parity evidence against the CLI.

**Architecture:** `packages/sdk` is a thin public TypeScript facade over `@inochi-agent-tools/core`. `packages/mcp` is a stdio adapter over that SDK. CLI, SDK, and MCP remain adapters over one semantic authority; neither new package may call the D ABI/native host directly or duplicate authoring logic.

**Tech Stack:** Node.js >=22, TypeScript 5.9, Vitest 3.2, npm workspaces, `@modelcontextprotocol/server@2.0.0`, `@modelcontextprotocol/client@2.0.0` for protocol-level tests, pinned Inochi2D `fdb241da048dbe330152f7b0015e2129dc392844` (`v0.8.7`), existing native/Creator acceptance harness.

**Spec:** `docs/superpowers/specs/2026-09-13-inochi-agent-tools-v1-design.md`

## Global Constraints

- Public/general-purpose only; no Away Message concepts or character-specific APIs.
- Exact upstream authority remains `fdb241da048dbe330152f7b0015e2129dc392844` on `v0_8`, `IN_VERSION = "v0.8.7"`.
- LDC remains >=1.40.0.
- `@inochi-agent-tools/core` remains the sole semantic authoring authority.
- Public MCP/SDK surfaces must never expose raw `in_*`, allocators, pointers, memory offsets, or implementation-specific native handles.
- Real `.inp` and real PNG artifacts are mandatory for integration/acceptance proof.
- Existing Creator and `m3:cli:ci` evidence must remain green; #10 extends it rather than replacing it.
- v1 MCP transport scope is stdio only. HTTP/auth/resources/prompts, UI/fork work, auto-rigging, and application adapters are out of scope.
- Strict RED -> GREEN for every behavior-bearing slice.

### Task 1: Public SDK Delegation Contract

**Files:** create the five `packages/sdk/*` files above; modify root `package.json` and `package-lock.json`.

**Produces:**

```ts
export interface AuthoringClient {
  createPuppet(input: CreatePuppetInput): Promise<CreatePuppetResult>;
  inspectPuppet(input: InspectPuppetInput): Promise<InspectPuppetResult>;
  validatePuppet(input: ValidatePuppetInput): Promise<ValidatePuppetResult>;
  savePuppet(input: SavePuppetInput): Promise<SavePuppetResult>;
  editPuppet(input: EditPuppetInput): Promise<EditPuppetResult>;
  evaluateParameters(input: EvaluateParametersInput): Promise<EvaluateParametersResult>;
}
export function createAuthoringClient(): AuthoringClient;
```

Use the exact existing core type names/signatures where they exist. If a core function is positional rather than object-based, the SDK method must delegate without inventing new authoring behavior; only a typed call-shape adapter is allowed.

### Task 2: MCP Tool Contract and Semantic Error Boundary

**Files:** create `packages/mcp/package.json`, `tsconfig.json`, `src/tools.ts`, `src/errors.ts`, `test/mcp-contract.test.ts`; modify root package/lockfile.

**Consumes:** `createAuthoringClient(): AuthoringClient` only.

**Exact v1 tool names:**
- `puppet.create`
- `puppet.open`
- `puppet.inspect`
- `puppet.validate`
- `puppet.save`
- `puppet.edit`
- `parameter.evaluate`

`puppet.edit` transports the existing semantic edit-operation array; texture import, hierarchy/Part creation, parameters, and bindings remain core-defined. `puppet.open` may delegate to the same inspect primitive as the CLI.

Success payload:
```ts
{ ok: true, result: semanticResult }
```
Failure payload:
```ts
{ ok: false, error: { code: semanticCode, message, details? } }
```
No stack traces/native internals in normal MCP responses.

- [ ] **Step 1 — RED:** assert exact tool names, schemas, malformed-argument rejection before semantic dispatch, stable success envelope, and typed error translation.
- [ ] **Step 2 — prove RED:** `npm run mcp:test` must fail because MCP package/registry is absent.

- [ ] **Step 4 — GREEN:** schemas expose semantic fields only (`input`, `output`, `name`, `operations`, `values`) and dispatch solely to `AuthoringClient`.
- [ ] **Step 5 — error boundary:** known core semantic errors preserve code/message/safe details; unknown failures map to one stable adapter failure without stack/native data.
- [ ] **Step 6 — verify:** `npm ci && npm run mcp:typecheck && npm run mcp:test` -> PASS, including forbidden-native-surface checks.
