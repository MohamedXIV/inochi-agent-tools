# v1.1 Packaging and Daily-Use Bootstrap Plan

Issue: #23

## Goal

Make the proven v1 CLI and MCP stack usable from outside a repository-root development shell without changing authoring semantics or weakening the pinned native contract.

## Distribution decision

v1.1 will first ship a reproducible repo-local bundle produced from a fresh checkout. The bundle is the supported daily-use unit: built CLI/MCP JavaScript plus the native host/bridge and launchers that resolve assets relative to their installation location. npm publication/release archives may wrap this bundle later, but are not required to make daily use correct.

## Architecture

- Keep CLI/SDK/MCP as adapters over the existing semantic core.
- Add one bootstrap/bundle authority that builds existing native + JS artifacts and stages them into a deterministic bundle layout.
- Launchers resolve bundle root from their own installation path, never from caller `process.cwd()`.
- Preserve explicit environment overrides for development/debugging, but installed defaults must be installation-relative.
- No new mesh, rigging, parameter, physics, or product-specific semantics.

## TDD execution

1. RED: add a packaged-path acceptance test that launches CLI and MCP from an unrelated temporary CWD and requires native discovery to succeed against real `.inp`/PNG artifacts.
2. GREEN: introduce the smallest installation-relative resolver/launcher and deterministic bundle builder needed to satisfy that test.
3. Extend the packaged smoke to cover real create/import/edit/evaluate/save/validate through CLI/MCP while preserving the v1 semantic path.
4. Add Windows PowerShell and WSL/Linux bootstrap/launcher coverage. Path handling must tolerate spaces and must not rely on shell CWD.
5. Add a single issue-specific acceptance command (planned name `v1.1:package:ci`) composing packaged smoke with `npm run v1:ci`.
6. Document fresh-checkout bootstrap, prerequisites, supported Windows/WSL boundary, rebuild/upgrade flow, troubleshooting, CLI invocation, and copy-paste stdio MCP client configuration.

## Acceptance evidence

- Fresh-checkout bootstrap produces the documented bundle.
- CLI launches from outside repo root and operates on a real puppet.
- MCP launches from client-style stdio configuration with unrelated CWD.
- Packaged real-artifact workflow covers create/import/edit/evaluate/save/validate.
- Windows/WSL launchers use installation-relative discovery and quote paths safely.
- `npm run verify`, `npm run v1:ci`, and `npm run v1.1:package:ci` are GREEN on the exact final head.
- Final PR audit shows no new authoring semantics, no Away-specific policy, and no unresolved review threads.

## Non-goals

No npm registry publication requirement, Creator UI changes, rigging semantics, auto-rigging, or downstream Away implementation.
